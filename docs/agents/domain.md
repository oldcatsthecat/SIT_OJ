# Domain docs

This repo uses one domain context. Before exploring an area, read the root `GLOSSARY.md` and relevant ADRs in `docs/adr/` when they exist. Their absence needs no setup action; `/domain-modeling` creates them when terms or decisions are resolved.

Use glossary terms in issues, proposals, hypotheses, and tests. If a needed term is missing, check the code's vocabulary and note a real gap for `/domain-modeling`.

Surface any conflict with an existing ADR explicitly.
